# 电力动态 POWHOT

电力行业公开信息聚合站，视觉与信息架构复刻 [aihot.news](https://aihot.news/?page=1)，
数据源接入本地已有的「电力资料每日采集」任务。

## 与上游采集任务的关系

```
电力资料获取/                        电力资讯站/
├── collector/run_all.py   ──┐      ├── build_site.py      数据构建
│   （每日 05:00 采集）       │      │   读取 reports/*.md + data/ 正文存档
├── data/<机构>/<日期>/<栏目>/│─────▶│   清洗正文 → 打标分类 → 产出 JSON
│   *.md 正文存档            │      └── site/               静态站点（可直接部署）
├── reports/YYYY-MM-DD.md  ──┘          ├── index.html
│   （采集日报，条目索引）                ├── assets/{style.css,app.js}
└── .state/seen.json                    └── data/{news.json,bodies/}
      （URL 去重库）
```

本站**不重复抓取**，只消费采集任务已经归档的成果，因此不会给源站带来额外压力。

## 使用

```bash
cd /Users/xiaodongzheng/WorkBuddy/电力资讯站

# 重建数据（读上游 reports/ 与 data/，清洗后写入 site/data/）
/Users/xiaodongzheng/.workbuddy/binaries/python/versions/3.13.12/bin/python3 build_site.py

# 本地预览
cd site && /Users/xiaodongzheng/.workbuddy/binaries/python/versions/3.13.12/bin/python3 -m http.server 8899
# 打开 http://127.0.0.1:8899
```

全量构建约 1.5 秒。构建是**幂等**的：重复运行结果一致，可安全用于每日自动化。

## 数据流细节

### 输入

- `reports/*.md`：采集日报。每份按 `## 机构（N 篇）` 分组，条目为
  `### [栏目] 标题`，其下含 `- 原文:` / `- 正文存档:` / `- **AI摘要**:` / `> 摘录:`。
- `data/<机构>/<日期>/<栏目>/<标题>.md`：正文存档，开头是元信息块（来源机构、
  栏目、发布日期、原文链接、附件），`---` 之后为正文。

### 清洗（针对政务/企业网站转 markdown 的典型噪声）

三个来源站的存档结构差异很大，清洗按"先分块、再逐层择优"处理：

1. **剥元信息块**：丢掉 `---` 之前的来源机构/栏目/发布日期字段
2. **分块与行式判定**：按空行切块；块内若短行（<50 字）占比 ≥35%，说明是
   列表/字段流结构（TRS 存档、公告明细），逐行保留；否则视为一个段落
3. **行内清洗**（`strip_inline_noise`）：
   - 从页脚标志截断（`扫一扫在手机打开当前页`/`网站地图`/`版权所有`/`ICP备`…）
   - 删除夹在正文中的导航词（`设为首页`/`机构概览`/`在线办事`…）
   - 删除政府站"目录项的基本信息 / 公开事项名称 / 索引号 / 制发日期"元信息
   - 删除夹在行内的时间戳（`2026-08-03 19:15 来源：xxx`）
   - 删除与条目标题重复的公文标题行（页面 h1 已展示）
4. **行级择优去重**（`dedupe_piecewise`）：**这是处理多粒度重复的关键**。
   TRS 类政务站的正文存档会把同一内容以三种粒度挤在一起，且用**单换行**分隔
   （不是空行），因此三遍内容落在同一个块里：①一段紧凑长文（导航+正文+页脚
   压在一行）②一份分段正文 ③一份逐字段行。判据是：长行若 ≥80% 的**字符位置**
   能被其他较短行覆盖，说明它只是合并版，丢弃它、保留粒度更细的版本。
   用字符位置而非 3-gram 覆盖率——字段拼接处的跨界 n-gram 在拆分版里并不存在，
   用 n-gram 会低估覆盖率而漏判。
5. **段内句子去重**（`dedupe_within`）：处理"正文 A + 正文 A"挤在同一段落里的
   情况。只在段落内部比对，**不做跨段落累积**——跨段累积会把"逐字段行"这种
   更可读的细粒度版本当成重复一并删掉。
6. **超长段落按句读切分**：政务站常把整篇压成一段，>600 字的段落按句号重组为
   约 260 字的多段，并处理切分点落在引号/括号中间的情况。

> 踩过的坑：早期版本用"整篇重复折叠 + 跨段落句子去重"的组合，对 TRS 的无句读
> 字段流会误判，把 2101 字的正文截到 341 字再被导航词规则清空 —— 170 条里有
> **66 条正文被误清空**。现方案上线后正文覆盖率 104/170 → **169/170**。

### 分类

主分类共 8 类，**仅按标题判定**，未命中时按采集栏目兜底：

| 分类 | 判定线索（节选） | 栏目兜底 |
|---|---|---|
| 安全生产 | 安全生产、应急、隐患、迎峰度夏 | — |
| 电力市场 | 现货、中长期、电价、售电、绿电交易 | 市场动态 |
| 新能源 | 光伏、风电、储能、氢能、绿电直连 | — |
| 电网建设 | 特高压、输配电、西电东送、并网 | — |
| 资质监管 | 许可、资质、12398、投诉举报、公示 | 监管动态 |
| 数据统计 | 装机、电量、运行情况、半年报 | — |
| 政策法规 | 征求意见、管理办法、实施细则、规划 | 通知公告 |
| 企业动态 | （兜底） | 公司要闻、中电联动态 |

> 刻意不做正文/AI 摘要兜底匹配——长文本中的泛词会污染分类
> （例：企业领导调研稿里提到"数字电网"就被误判为电网建设）。

### 输出

- `site/data/news.json`：列表数据（不含正文，约 190 KB）。含 `stats` 统计块。
- `site/data/bodies/<id>.json`：按 id 的正文与附件，详情页按需加载。

## 站点功能

- 时间线列表：按发布日分组、sticky 日期头、三栏栅格（时间 64px + 轨道 22px + 卡片）
- **原文直接呈现，不靠跳转**：详情页把 **AI 摘要**（青绿高亮块）与**原文全文**
  垂直平铺，一进页面即可读完；源站链接降级为底部的次要入口（"访问源站"）。
  卡片同屏展示 AI 摘要与原文摘录（4 行），并标注"全文 N 字 ›"提示可读全文。
- 主题筛选：8 个分类 tab + 侧栏分类导航
- 来源筛选：下拉选择 + 侧栏机构导航（含机构色标）
- 全站搜索：标题、摘要、AI 摘要、标签、机构（快捷键 `/` 聚焦）
- 每日要闻：按日期归档的目录页，可跳转单日
- 收藏：localStorage 本地存储，无需登录
- 明暗主题、移动端底部 tab、回到顶部

## 自动化

每日闭环由两个 WorkBuddy 自动化任务串起：

| 时间 | 任务 | 职责 |
|---|---|---|
| 05:00 | 电力资料每日采集 | 抓取 6 类信源 → `data/` + `reports/`，生成 AI 摘要 |
| 05:45 | 电力资讯站每日构建与发布 | `build_site.py` → 重新发布站点 |

两者解耦：即使采集失败，站点仍会基于已有归档重建，不会白屏。
