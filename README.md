# 电力动态 POWHOT

电力行业公开信息聚合站。信息架构与视觉复刻 [aihot.news](https://aihot.news/)，
数据消费自本机已有的「电力资料每日采集」任务。

- 线上站点：https://powhot-electric-news.app.workbuddy.host/
- 代码仓库：https://github.com/ChenShi-Tech/power-news-site （公开）
- 发布应用 ID：`wbapp_GzlEj6ok9YYQcozvEFLWs2`（每日自动化按此 appId 复用，链接保持不变）

## 数据流

### 输入：直接扫 `data/` 归档，不依赖 `reports/` 索引

`reports/YYYY-MM-DD.md` 是采集器按天生成的文件，**同一天多次采集（如分批 `--only`）
会互相覆盖**，导致先跑批次的条目从索引里消失。因此构建改为全量扫描 `data/`：

- 每个正文存档 md 头部都有 `来源机构 / 栏目 / 发布日期 / 原文链接 / 摘要`
- `发布日期` 是真实发布日（目录名是采集日，两者可能不同）
- AI 摘要由采集自动化写入 `reports/`，构建时按 URL 关联回收

### 正文清洗

针对政务/企业网站转 markdown 的典型噪声，按「先分块、再逐层择优」处理：

1. **剥元信息块**：丢掉 `---` 之前的来源机构/栏目/发布日期字段
2. **分块与行式判定**：按空行切块；块内若短行（<50 字）占比 ≥35%，说明是列表/字段流
   结构（TRS 存档、公告明细），逐行保留；否则视为一个段落
3. **行内清洗**（`strip_inline_noise`）：从页脚标志截断、删除夹在正文中的导航词、
   删除政府站「目录项的基本信息 / 公开事项名称 / 索引号 / 制发日期」元信息、
   删除行内时间戳、删除与条目标题重复的公文标题行
4. **行级择优去重**（`dedupe_piecewise`）：**多粒度重复的核心处理**。TRS 存档会把同一
   内容以三种粒度挤在一起，且用**单换行**分隔（不是空行），三遍落在同一个块里。
   判据是长行若 ≥80% 的**字符位置**能被其他较短行覆盖，则丢弃它、保留粒度更细的版本。
   用字符位置而非 3-gram —— 字段拼接处的跨界 n-gram 在拆分版里并不存在，会低估覆盖率
5. **段内句子去重**（`dedupe_within`）：处理「正文 A + 正文 A」挤在同一段落里的情况。
   **只在段落内部比对，不跨段累积**，否则会把逐字段行当成重复一起删掉
6. **超长段落切分**：>600 字的段落按句读重组为约 260 字的多段

### 分类

8 个主分类，**仅按标题判定**，未命中时按采集栏目兜底：

| 分类 | 判定线索（节选） | 栏目兜底 |
|---|---|---|
| 安全生产 | 安全生产、应急、隐患、迎峰度夏 | — |
| 电力市场 | 现货、中长期、电价、售电、绿电交易 | 市场动态 |
| 新能源 | 光伏、风电、储能、氢能、绿电直连 | — |
| 电网建设 | 特高压、输配电、西电东送、并网 | — |
| 资质监管 | 许可、资质、12398、投诉举报、公示 | 监管动态 |
| 数据统计 | 装机、电量、运行情况、半年报 | — |

> （例：企业领导调研稿提到「数字电网」就被误判为电网建设）。

### 配图

采集器 `common.py` 新增 `extract_image_urls` + `Fetch.download_image` +
`Storage.save_images`：从正文 HTML 提取 `<img>`（含懒加载属性），过滤
logo/icon/二维码/广告等 UI 元素，带 Referer 下载到 `data/.../images/<文章hash>/`，
再用 ImageMagick 限长边 1600px、质量 84 压缩。

构建时 `collect_images` 把 md 中 `![图片](...)` 引用的图复制到 `site/images/<id>/`，
写入 `news.json` 的 `images` 字段，卡片与详情页渲染为图片网格，支持点击放大。

> 现实约束：政务源（国家能源局、发改委、南方电网、区域监管局）的新闻绝大多数是
> 纯文字公文，实测**没有内容配图**（页面里的图都是搜索/分享等 UI 图标）。
> 真正带配图的是中国能源报和北极星电力市场网，这也是引入这两个源的动因之一。

### 主题与报告

- `topics.json`：26 个主题，分「机构与主体 / 区域市场 / 主题方向」三组。
  命中判定只看**标题 + 标签**，避免长文本泛词污染
- `reports.json`：日报（按日期）/ 周报（按 ISO 周）/ 月报（按自然月），
  三者结构一致（条目 id 列表 + 分类统计 + 预计阅读时长），前端共用一个报告视图

## 站点功能

- **时间线**：按发布日分组、sticky 日期头、三栏栅格（时间 64px + 轨道 22px + 卡片）。
  无发布时间的条目在时间列显示机构短名（如"华北""北极星"），避免大面积留白
- **原文直接呈现**：详情页把 AI 摘要与原文全文**垂直平铺**，一进页面即可读完；
  源站链接降级为底部次要入口。卡片标注「全文 N 字 ›」
- **配图**：卡片网格 + 详情页画廊 + 点击放大；保持原始宽高比（配图比例跨度
  0.71~10.9，固定比例裁切会丢内容），宽高比 > 2.6 的超宽图独占整行
- **附件下载**：政策原文 PDF / Excel / zip 等同步到站点，详情页可直接下载
  （单文件 ≤ 5MB，全站累计 ≤ 40MB，超限的在页面上提示去源站取）
- **主题**：`#/topics` 主题卡片网格，点击进入该主题的条目列表
- **报告**：`#/daily` `#/weekly` `#/monthly`，左侧周期目录 + 右侧编号条目
- **趋势**：`#/about` 有「每日发布量（按分类堆叠）」柱状图 ——
  现货市场类新闻量突然放大往往对应政策窗口期
- **RSS 订阅**：`/feed.xml`（最近 60 条，含摘要、配图与原文链接）
- **筛选与搜索**：8 个分类 tab、来源下拉、侧栏机构导航、全站搜索（快捷键 `/`）
- **相关阅读**：按标签重合度排序（标签 ×2 + 同分类 + 同机构），不再是同分类硬凑
- **收藏**：localStorage 本地存储；**明暗主题**；移动端底部 tab；回到顶部

## 数据质量保障

构建脚本对以下几点做了主动防护，避免"看起来正常但内容缺失"：

- **标题重复合并**：判据要求「标题完全相同 **且** 正文开头包含度 ≥ 0.90」。
  只用标题相似度会误杀 —— 实测把「华中/华北/西北能源监管局召开…总结会」
  这类**不同机构的独立新闻**当成重复合并了
- **站点推广素材剔除**：同一张图（内容 MD5）在 ≥2 篇文章中出现即判定为
  站点素材（公众号二维码、宣传横幅）。这类图 URL 里没有 logo/qrcode 关键词，
  按文件名规则抓不出来，只能靠跨文章重复度识别
- **配图串图防护**：图片按文章 hash 分目录存放，避免同一天多篇文章的
  `images/1.jpg` 互相覆盖
- **附件体积控制**：原始附件合计 108MB（含单个 18MB 的 zip），
  经单文件 5MB + 全站 40MB 双重限制后收敛到约 31MB

## AI 摘要

站点的「AI 摘要 + 原文」双版本中，摘要来自两处：

1. 每日采集自动化写入 `reports/*.md` 的 `AI摘要` 字段（针对当日新增）
2. `gen_summaries.py` 用 LLM 补生成，结果存 `summaries.json`（针对历史缺口）

```bash
# 补齐缺失的摘要（默认走火山引擎豆包，OpenAI 兼容接口）
python3 gen_summaries.py            # 只补缺失的
python3 gen_summaries.py --limit 10 # 试跑
python3 gen_summaries.py --redo     # 全部重生成

# 也可用 OpenRouter（需能访问境外；注意 google/* 模型对中国区返回 403）
SUMMARY_BACKEND=openrouter OPENROUTER_API_KEY=sk-or-... python3 gen_summaries.py
```

构建时两处摘要合并（`summaries.json` 优先）。脚本支持增量续跑：
中途中断后重跑会跳过已生成的条目。

## 失败告警

`notify.py` 在构建/发布异常时推送钉钉消息，避免"静默失败"：

```bash
python3 notify.py --status fail --text "站点构建失败，线上保留上一版本" --extra "<错误摘要>"
python3 notify.py --status ok   --text "今日 28 条新增，已发布"
```

webhook 从环境变量读取，**未配置时静默跳过**（不会中断自动化）：
`POWHOT_DINGTALK_WEBHOOK`、`POWHOT_DINGTALK_SECRET`（加签用）。

## 自动化

每日闭环由两个 WorkBuddy 自动化任务串起：

| 时间 | 任务 | 职责 |
|---|---|---|
| 05:00 | 电力资料每日采集 | 抓取 8 个信源 → `data/` + `reports/`，下载配图，生成 AI 摘要，导入 ima 与 Notion |
| 06:30 | 电力资讯站每日构建与发布 | `build_site.py` → 补摘要 → 重新发布 → curl 验证 → 通知 |

两者解耦：即使采集失败，站点仍会基于已有归档重建，不会白屏。

另有 **GitHub Actions**（`.github/workflows/deploy-pages.yml`）作为独立发布链路：
推送到 main 后自动把 `site/` 发布到 GitHub Pages（含数据完整性校验）。
它只部署产物、不做构建 —— 因为采集归档不在仓库里。

## 已知限制

- **历史数据无法补齐**：各源站的列表页只保留最近的文章（南方电网仅当前月、
  北极星无历史归档、国家能源局日期目录 404）。北极星的文章 ID 虽是全局递增，
  但与 URL 中的日期段不对应，无法按 ID 区间枚举。因此 2026-08-07 ~ 08-23
  共 27 天的空白无法回溯，只能保证今后不再断档
- **部分源没有发布时间**：北极星、南方电网的页面只给日期不给时分，
  这些条目在时间列显示机构短名
- **媒体源版权**：站点与仓库均为公开，其中北极星电力市场网、中国能源报的
  内容是媒体版权内容（政务源的公文可依《政府信息公开条例》转载）。
  如需降低风险可改为只保留摘要 + 原文链接
